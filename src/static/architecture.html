Architecture

We did not shrink the model. We shrank its working set.

Jamii Afya separates where model parameters live from how much memory must be resident for the next token. The full sparse model stays on disk; the runtime stages only the bounded expert working set it needs.

The memory boundary

A 12.26 GB model does not require 12.26 GB of resident RAM.

The routed expert bank is storage-heavy, but only a subset of experts is needed for each token. Jamii Afya keeps explicit staging slots in memory and reuses them as routing changes.

K4/16 execution

Execute the top four routed experts while normalizing against the probability mass of the top sixteen. Execution count and router reference mass are kept separate.

Selective Q2_K

Requantize the storage-dominant routed expert tensors while preserving more suitable types for sensitive dense, shared, router, embedding, and state-space components.

Bounded staging

A fixed pool of 755 slots and 80 pinned experts stages missing tensors, reuses slots, and evicts explicitly. The cache shape does not grow with the model.

Cross-platform runtime

The repository packages the pinned llama.cpp runtime for Linux, macOS, and native Windows, with model hash verification and offline operation after setup.

What is novel here

The claim is the composition, not a false invention story.

We are not claiming to have invented MoE execution, expert offloading, SSD-backed inference, or quantization independently. The contribution is the measured operating point: a much stronger sparse model, a real router, K4/16, selective routed-expert quantization, explicit bounded staging, and CPU-only llama.cpp below 3 GB RSS.

No weight-level fine-tuning was performed. The reusable layer is the inference system. Healthcare is the current submission domain; the same runtime can be adapted to agriculture, education, coding, enterprise work, and local-language tools.
